# vault-tool project decisions

- This public repository owns the local encryption engine. `wlyaaaaa/Key` is a separate private ciphertext repository; follow `docs/key-repository-workflow.md` for that cross-repository operation. Never commit real passwords, keyfiles, plaintext, or private vault contents here.
- User-selected source files are preserved by default. Only an explicit cleanup request may remove files that this run archived and verified unchanged; a failed, changed, linked or uncertain file stays. Do not treat encryption success as permission to delete an original.
- A candidate ciphertext must be verified before commit and read back afterward. Keep a non-overwriting recovery copy before replacing an existing vault. `rebuild --out` creates a separate verified copy; it does not replace the old vault.
- VAULT03 may hold two independently unlocked slots. `passwd` changes only the opened slot and preserves the other ciphertext and existing KDF. Changing a shared keyfile setting or capacity requires rebuild with the necessary known credentials; never infer that an unopened slot is empty.
- Legacy VAULT01/02 reading and migration remain supported. Container structure checks alone do not prove password correctness or recoverability. Recovery requires the password and the exact keyfile bytes if one was used.
- AI-facing `info`, `doctor`, `assess`, `plan`, `credential-plan` and `recovery-check --self-test` provide metadata or synthetic checks only. They do not receive real passwords, decrypt real vaults, list private source/decrypted filenames, or execute a recommended step. An explicit `--vault-file` must not fall back to the default vault.
- Local view/edit and explicit export can handle plaintext; never capture their output in AI logs. Export does not overwrite conflicting files, reports partial writes honestly, and ordinary diagnostics do not clean plaintext residue. `clean-plaintext --confirm` is a separate explicit operation.
- `Publish-KeyVaultToGitHub.ps1` only targets a confirmed private repository and reports success after remote byte readback. `ProtectRemoteReadme` is a separate explicit action; do not combine it with routine ciphertext publication or rewrite old Git history.
- Tests must use fictional passwords, isolated temporary files and mocked GitHub responses. Do not inspect a real keyfile/vault, publish/recover real data, or install/restore to the live machine as part of this repository's tests.
